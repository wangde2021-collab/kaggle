# LB 差距核查（2026-11-19）

问题：25 折 CV 0.8413，Public LB 0.76315，差 0.0782。

## 核查结果（逐项）

### 1. CV 算得对不对 —— 对，复现一致

- 从保存的 OOF 文件重算：E3 0.8413±0.0235，B6 0.8305，tuned_lgbm/xgb 0.8391，E1 0.8334，E2 0.8390，E5 0.8346，E6 0.8409，与实验表完全一致。
- 折分层正确：每折正例率 38.2%–38.8%，全体 38.38%，每折 178–179 人。
- 结论：CV 计算没有算错。

### 2. E3 权重是不是折内求的 —— 是，干净

- 代码（scripts_stage6.py）：每折权重用其余 24 折 OOF 优化 LogLoss；报告分数用的是逐折权重。
- 复核：用全局权重直接算全部 OOF 得 0.8415，与折内权重版 0.8413 相差 0.0002，权重环节没有虚高。
- 各 repeat 内最优权重稳定：lgbm 0.75–0.83，svc 0.116–0.17，knn 0.0–0.086；全局权重 0.816/0.155/0.029 与之一致。

### 3. 选择偏差 —— 很小，约 +0.0006

- 自举估计（25 折有放回重采样 2000 次，8 个候选取最高）：选择偏差 +0.0006。
- 关键证据：E3 与 tuned_lgbm 配对差仅 +0.0022（p=0.2951，胜 12/25），与 tuned_xgb +0.0022（p=0.3830），与 E6 +0.0004（p=0.8218）。前四名候选都在 0.0023 以内，“E3 最好”在噪声范围内。E3 对 B6 的 +0.0108（p=0.0012）是真的，但那主要是特征工程（F_best 对 F0）加调参的功劳，不是集成的功劳。

### 4. 排行榜噪声 —— 重要修正：Public LB 用的是全部 418 行，不是 209 行

- 暴力验证：把四次提交分数（0.76315、0.77751、0.75358、0.75598）对分母 100–418 做截断匹配，只有 418 同时满足四个。209 行下 0.76315 对不上任何整数正确数（159/209=0.76077，160/209=0.76555）。
- 所以 E3 的 LB 是 319/418。标准误 = 0.0208，95% 区间 [0.7224, 0.8039]。差距 0.0782 相当于 3.76 个标准误，单靠噪声很难解释（p 约 0.0002）。噪声能解释约 2 个点，剩下的 5–6 个点是真实差距。
- 注：所谓“LB 只用一半 test”是常见误解，Titanic 的 Public LB 就是全部 test 集。

### 5. 分布差异 —— 对抗验证复核通过，无系统性偏移

- 复现：F0 特征 AV AUC 0.5017（各折 0.5326/0.5309/0.5139/0.4757/0.4554），与上轮一致。
- F_best 特征（本轮实际用的 Title、Sex_Pclass）AV AUC 0.5084，同样接近 0.5。
- 边缘分布上 Embarked 确有偏移（S 72.4%→64.6%，C 18.9%→24.4%），Mrs +3.1 个点，male_3 -4.0 个点；但联合分布上 train/test 几乎不可分，且 Embarked 的偏移方向（S 少、C 多）对生还有利，解释不了分数下降。分布差异最多是次要因素。

### 6. 特征泄漏复查 —— 没发现泄漏

- F_best = 数值 [Pclass, Age, SibSp, Parch, Fare] + 类别 [Sex, Embarked, Title, Sex_Pclass]，全部不含标签。
- Title 从 Name 提取，Sex_Pclass 是 Sex 与 Pclass 组合，都是行内信息。
- TicketFreq 用 train+test 合并计数，技能允许且不含标签；G3 在消融中已被否决，不在 F_best 里。
- Age 填补：F_best 没用分组填补，预处理器在每折训练折内算中位数，无泄漏。
- G8 组生还已排除。
- 结论：特征环节干净。

### 7. 提交文件本身 —— 没交错

- sub_001：418 行，列 PassengerId/Survived，PassengerId 顺序与 test.csv 完全一致，生还 149 人，生还率 0.3565；根目录 submission.csv 与 sub_001 完全一致；提交编号 58565101 的文件名就是 sub_001。
- 与 CV 平均的 test 预测（test_preds/E3_weighted.npy）有 11 人不同：这是全量重训与 25 折模型平均的正常差异，不是交错文件。

### 8. 全量重训环节 —— 与 CV 的差异已量化，结论是没拖后腿

- LGBM：CV 时每折早停（平均最佳迭代 115.44），全量重训固定 133 棵（115.44×1.15），5 种子，参数与调参结果一致（lr 0.076、num_leaves 22、max_depth 6）。
- 诚实 CV（提交版精确配置重跑 25 折：LGBM 固定 133 棵无早停，SVC/KNN 调参，权重固定 0.816/0.155/0.029）：E3 得 0.8440±0.0204，比已报的 0.8413 还高 0.0027（配对差 +0.0027，se 0.0019，不显著）。
- 单独看：固定 133 棵的 LGBM 诚实 CV 是 0.8334，比早停版 0.8391 低 0.0057——早停确实让单模型 CV 虚高约 0.6 个点；但集成后这个差距被抹平甚至反超，说明早停不是 LB 差距的主因。
- SVC/KNN：CV 与全量重训都是单种子（tuned_svc/tuned_knn 的 n_seeds=1），无不一致。

## 诊断结论：差距最可能由什么造成

差距 0.0782 的分量估计：

1. **LB 抽样噪声：约 2 个点**（标准误 0.0208，1σ）。LB 是 418 行上的一次测量，0.763 这个数本身就有 ±2 个点的晃动。
2. **训练集内 CV 看不到的泛化差距：约 5–6 个点（主因）**。25 折 CV 的 25 折都是同一批 891 人的重排，折间高度相关，CV 均值的真实不确定性比 naive 标准误 0.0047 大得多（各 repeat 均值 0.8339–0.8496，跨 repeat 波动约 1.6 个点）。更关键的是：特征选择（消融）、调参（Optuna 目标 rep0）、集成选择（E1–E6 挑最高）全都在同一套 25 折上完成，CV 分数里自带“在同一批数据上挑最好”的乐观。逐项量化后单项都不大（选择偏差 +0.0006、调参 rep0 偏好约 +0.002、早停在集成层面约 0），但它们叠加在“CV 只能衡量对同一批人的泛化、衡量不了对新一批 418 人的泛化”这个结构性缺口上。891 行的小数据上，CV 0.84 的模型落到 LB 0.76–0.78 是 Titanic 的常见现象。
3. **分布差异：最多 0–1 个点**。AV 接近 0.5，Embarked 边缘偏移真实存在但方向有利，不是主因。
4. **权重、泄漏、交错文件：0**。三项都已排除。

一句话：CV 没算错，权重没漏水，文件没交错；差距主要是一半噪声、一半小数据上 CV 本身看不到的泛化缺口——模型在 891 人上调得越精，在新 418 人上回落得越多。

## 下一步建议（只建议，不动手）

1. **最该做的：拿一个 LB 锚点**。提交一次 B1 性别规则（或 B6）看 LB，代价 1 次提交（今天还剩 9 次）。如果 B1 的 LB 也在 0.76 附近，说明是 test 集本身难，E3 没毛病；如果 B1 的 LB 明显高于 0.763，说明 E3 在 test 上真的输给了简单规则，问题在模型。
2. **下一轮优先查 CV 而不是堆模型**：做一次嵌套 CV（外层 5 折评估，内层做特征选择+调参+集成选择），拿到“选完之后”的真实泛化估计；或者把 25 折拆成“选择用”和“评估用”两部分，评估用折不参与任何选择。
3. **早停改掉**：以后 LGBM/XGB 用固定迭代数（或在训练折内再划验证集做早停），不要用验证折早停——单模型虚高 0.6 个点，决策门会被误导。
4. **阈值和校准**：提交预测生还率 35.65% 低于 train 的 38.38%，若 test 真实率接近 train，模型偏保守；下一轮可在折内校准阈值（技能第 6.3 节，胜折 ≥18/25 才采用）。
5. **不要用 LB 当验证集反复试探**：每天最多 1–2 个探索性提交，LB 只是 418 行的一次测量，±2 个点的噪声下追 LB 很容易过拟合 LB。
